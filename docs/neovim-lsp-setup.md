# Neovim LSP Setup for Swift/Xcode Projects

## How It All Fits Together

```
Neovim → LSP client → sourcekit-lsp → buildServer.json → xcode-build-server → DerivedData index
```

### The Pieces

| Layer | What it is | Where it lives |
|---|---|---|
| **Neovim LSP client** | Built-in LSP support in Neovim (`vim.lsp`). Speaks the Language Server Protocol to any language server. | Built into Neovim |
| **nvim-lspconfig** | Plugin providing default configs (command, filetypes, root detection) for ~100 language servers. Without it you'd write all that boilerplate yourself. | `~/.local/share/nvim/site/pack/` |
| **sourcekit-lsp** | Apple's language server for Swift. Provides completions, diagnostics, go-to-definition, etc. Needs to know how your project is compiled. | Ships with Xcode |
| **xcode-build-server** | Bridge between sourcekit-lsp and Xcode projects. sourcekit-lsp can handle SPM packages natively, but `.xcodeproj` targets need this translator. | `brew install xcode-build-server` |
| **buildServer.json** | Config file that tells sourcekit-lsp "ask xcode-build-server for build info." Generated by xcode-build-server. | Project root (e.g. `ios/`) |
| **DerivedData** | Xcode's build output. Contains the symbol index that sourcekit-lsp reads to resolve types across files. | `~/Library/Developer/Xcode/DerivedData/` |

### What Breaks If You Skip a Piece

- **No `buildServer.json`** — sourcekit-lsp treats each Swift file in isolation and can't find types from other files ("Cannot find 'PrimaryButton' in scope")
- **No build (empty DerivedData)** — no index to read, same "not found" errors
- **No nvim-lspconfig** — sourcekit-lsp won't start automatically when you open a Swift file
- **No xcode-build-server** — sourcekit-lsp can't understand `.xcodeproj` build targets

## Setup Steps for a New Xcode Project

1. **Build the project in Xcode** (Cmd+B) or via CLI:
   ```bash
   xcodebuild -project MyApp.xcodeproj -scheme MyApp \
     -destination 'platform=iOS Simulator,name=iPhone 17 Pro' build
   ```

2. **Generate `buildServer.json`** in the directory containing the `.xcodeproj`:
   ```bash
   cd path/to/ios
   xcode-build-server config -project MyApp.xcodeproj -scheme MyApp
   ```

3. **Restart Neovim** — sourcekit-lsp picks up `buildServer.json` on launch and uses the build index.

A brief flash of errors on startup is normal — sourcekit-lsp starts before the build server responds with index data.

## When to Re-run

- **After adding new files** — rebuild in Xcode (Cmd+B) so the index updates
- **After cleaning DerivedData** — rebuild, since the index was wiped
- **After moving the project** — re-run `xcode-build-server config` to update paths in `buildServer.json`

## Config Files

- Neovim LSP config: `~/.config/nvim/lua/plugins/lsp.lua`
- Treesitter config: `~/.config/nvim/lua/plugins/treesitter.lua`
- Keymaps: `~/.config/nvim/lua/keymaps.lua`
